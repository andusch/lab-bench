# Package LabBench for Linux

Status: not done

## Problem

A student on Linux can open the desk only from this checkout. There is no package that installs it.

## Outcome

`npm run tauri build` writes the Linux packages already selected by `bundle.targets` set to `"all"` in `src-tauri/tauri.conf.json`. The Debian package installs the P1 desk. The installed LabBench loads a CSV, plots both uncertainties, fits degree 1, 2, or 3, and writes a PNG and a Markdown file. The same build writes the RPM and the AppImage.

## Acceptance

- `npm run tauri build` finishes on Linux, and `bundle.targets` is still `"all"`.
- On a 64-bit PC the build writes `src-tauri/target/release/bundle/deb/LabBench_0.1.0_amd64.deb`.
- That build also writes `src-tauri/target/release/bundle/rpm/LabBench-0.1.0-1.x86_64.rpm` and `src-tauri/target/release/bundle/appimage/LabBench_0.1.0_amd64.AppImage`.
- On another CPU, only the architecture tag in those file names changes.
- Installing the `.deb` adds LabBench. Launching it opens the desk with no dev server.
- The installed desk fits `samples/hookes-law.csv` at degree 1 with a slope between 17.5 and 18.5 N/m.
- A fit of `samples/capacitor-discharge.csv` has no time constant.

## Tests

- Run `npm run tauri build` and confirm the `.deb`, the `.rpm`, and the AppImage.
- Install the `.deb`, launch LabBench, and fit Hooke's law at degree 1.
- Fit the capacitor sample and confirm the result has no time constant.

## Non-goals

- A Windows installer. That belongs to P2-02.
- A macOS disk image. That belongs to P2-03.
- Install steps in the README. That belongs to P2-04.
- Snap, Flatpak, and a cross-compiled ARM package.
- Committing the packages into git. They stay build output under `src-tauri/target/`.
- A new fit, a time constant, serial input, Typst, and a launch post.
