# Explain how to install LabBench

Status: done

## Problem

The packages from P2-01, P2-02, and P2-03 are build output. A student who is not in this checkout cannot tell which file to install.

## Outcome

`README.md` tells that student how to install LabBench and open the P1 desk. Linux uses the Debian package from P2-01. Windows uses the setup program from P2-02. macOS uses the disk image from P2-03. The steps do not ask for Node, Rust, or a clone of this repo. The README no longer lists a packaged installer as missing from version 1.

## Acceptance

- The README says a 64-bit Debian or Ubuntu student installs `LabBench_0.1.0_amd64.deb`.
- The README says a 64-bit Windows student runs `LabBench_0.1.0_x64-setup.exe`.
- The README says a Mac student opens the `.dmg` and drags LabBench to Applications. Apple Silicon uses `LabBench_0.1.0_aarch64.dmg`. An Intel Mac uses `LabBench_0.1.0_x64.dmg`.
- One sentence names `LabBench-0.1.0-1.x86_64.rpm` as the Fedora package, and one sentence says `LabBench_0.1.0_amd64.AppImage` runs without installing.
- Those steps do not clone the repo and do not run `npm`.
- "Packaged installers" is no longer in the list of what version 1 does not do.
- That list still names nonlinear least squares, Typst and PDF, a live serial stream, and a launch post.

## Tests

- Read the install section and confirm each system names one file and one install action.
- Confirm the steps do not mention `git clone` or `npm`.
- Read "What version 1 does not do" and confirm nonlinear least squares, Typst and PDF, a live serial stream, and a launch post are still listed.

## Non-goals

- Building the packages. That belongs to P2-01, P2-02, and P2-03.
- A download site.
- A Show HN post, and any other launch announcement.
- Marking P2 done.
- A change to the plot, the fit, or the export.
